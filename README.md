# BackupPilot

macOS 홈 디렉터리를 외장 SSD로 백업하고 되돌리는 SwiftUI 앱입니다.
Codex CLI가 계획을 검토하고, 오류를 진단하고, 자연어 지시를 해석하고, 복원 결과를 정리해 줍니다.

OS 재설치를 앞둔 상황을 전제로 만들었습니다.

---

## 무엇을 해결하는 앱인가

외장 SSD는 보통 **exFAT**입니다. 그냥 복사하면 두 가지가 조용히 망가집니다.

| 문제 | 결과 |
|---|---|
| POSIX 권한이 보존되지 않음 | `~/.ssh/id_ed25519`(0600)를 복사해 되돌리면 `ssh`가 **"permissions are too open"** 으로 거부 |
| 할당 블록이 128KB | 6바이트 파일이 디스크에서 **131,072바이트**를 차지 (실측) |
| 확장속성이 `._` 파일로 분리 | 파일마다 짝이 하나씩 더 생기고, 그것도 한 블록씩 먹음 |

이 앱은 대상 볼륨의 파일시스템을 먼저 확인하고, 항목마다 방식을 갈라 줍니다.

- **tar.gz** — 권한이 중요한 경로(`.ssh`, `.claude`, `.codex` 등)와 파일이 아주 많은 경로(소스 디렉터리).
  권한·심볼릭링크·확장속성이 보존되고 블록 증폭도 사라집니다.
- **평문 복사(rsync)** — 나머지. Finder에서 바로 열람할 수 있습니다.

### 소스 디렉터리는 이름이 아니라 내용으로 찾습니다

소스를 홈 어디에 두는지는 사람마다 다릅니다(`dev`, `src`, `Projects`, `work`, …).
흔한 이름은 목록으로 갖고 있지만, 거기 없는 이름을 쓰는 경우가 더 많습니다.

그래서 **홈 최상위에서 git 저장소를 품은 폴더를 찾아** 계획에 올립니다.
`~/mycompany` 에 소스를 두었어도 잡힙니다. 표준 폴더(`Documents`, `Library` …)와
클라우드 동기화 폴더(`Dropbox`, `OneDrive` …)는 보지 않습니다 — 후자는 어차피 원격에 사본이 있습니다.

하나도 찾지 못하면 계획 화면에 경고가 뜹니다. 계획은 존재하지 않는 경로를 조용히 버리기 때문에,
이 경고가 없으면 **가장 잃으면 안 되는 것이 아무 표시 없이 빠진 채** 백업이 끝납니다.
자동으로 잡히지 않는 폴더는 **「폴더 추가」** 로 직접 넣을 수 있습니다(홈 안쪽만).

실측 예 (이 앱의 로그에 그대로 찍힙니다):

```
Documents 완료 — 66 KB → 디스크에서 4.1 MB, 0초
```

## 빌드와 실행

```bash
./build-app.sh          # 릴리스 빌드 + .app 번들 조립 + 임시 서명
./build-app.sh --run    # 빌드 후 바로 실행
./build-app.sh --debug  # 디버그 빌드
```

Xcode 프로젝트 파일 없이 SwiftPM만 씁니다. 산출물은 `build/BackupPilot.app`.

요구 사항:
- macOS 14 이상
- `rsync` — Homebrew판(3.x)이 있으면 진행률이 퍼센트로 나옵니다.
  없으면 시스템 `openrsync`로 떨어지고, 이때는 파일 수로 진행률을 근사합니다.
- `codex` — 없어도 백업·복원은 그대로 됩니다. LLM 기능만 비활성화됩니다.

### 권한

`~/Documents`, `~/Desktop`, `~/Downloads`, 외장 볼륨에 접근할 때 macOS가 물어봅니다. 허용하세요.
`~/Library` 하위까지 백업하려면 **시스템 설정 > 개인정보 보호 및 보안 > 전체 디스크 접근 권한** 에
`BackupPilot.app`을 추가해야 합니다.

⚠️ 두 가지를 알아 두세요.

- **`open build/BackupPilot.app` 으로 실행하세요.** 번들 안의 실행 파일을 터미널에서 직접 실행하면
  TCC 가 권한을 앱이 아니라 터미널에 귀속시켜서, 앱에 준 권한이 적용되지 않습니다.
- **재빌드하면 권한이 풀립니다.** `build-app.sh` 는 임시 서명(ad-hoc)을 쓰는데, 이 경우 macOS 가
  번들 ID 가 아니라 cdhash 로 앱을 식별합니다. 빌드할 때마다 cdhash 가 바뀌므로 이전 허용 기록이
  무효가 됩니다. 권한을 초기화하고 다시 받으려면:

  ```bash
  tccutil reset SystemPolicyRemovableVolumes com.dkkang.backuppilot
  tccutil reset All com.dkkang.backuppilot
  ```

  자주 재빌드한다면 키체인에 자체 서명 인증서를 만들어 `--sign -` 대신 그것으로 서명하세요.
  designated requirement 가 인증서에 묶여서 재빌드해도 허용이 유지됩니다.

## Codex는 어떤 역할인가

다섯 가지 일을 합니다. 모두 `codex exec --output-schema`로 **구조화 JSON**을 받습니다.
자유 문장을 파싱하면 모델 말투가 바뀔 때마다 앱이 깨지기 때문입니다.

1. **계획 상담** — 디스크 상태와 용량 예측을 넘기고, 포함/제외와 방식 제안을 받습니다.
2. **환경 조사 제안** — 설치된 소프트웨어 목록을 넘기고, 그 환경에서 백업해야 할 경로를 받습니다.
3. **오류 진단** — 실패 로그를 넘기고 원인과 조치 단계를 받습니다.
4. **자연어 명령** — 문장을 실행 가능한 계획 변경으로 옮깁니다.
5. **검증 리포트** — 복원 후 기준값 대조 결과를 사람 말로 정리합니다.

2번이 나머지와 다른 점: 다른 넷은 홈 디렉터리와 실행 결과만 보지만, 이것은 **홈 밖**을 봅니다.
홈을 훑어서는 `Library/Application Support/` 아래 어느 디렉터리가 중요한지 알 수 없는데,
"무엇이 설치되어 있는가"를 알면 판단이 섭니다. 제안은 표시만 되고 계획을 자동으로 바꾸지 않습니다.

### 무엇이 전송되는가

Codex 기능을 쓰면 아래가 `codex` CLI 를 거쳐 모델로 나갑니다. **파일 내용은 보내지 않습니다.**

| 기능 | 전송되는 것 |
|---|---|
| 계획 상담 · 자연어 명령 | 백업 항목의 **상대경로**(`Documents`, `.ssh`, `dev` …), 각 항목의 크기·파일 수·선택 상태, 대상 볼륨의 파일시스템·용량 |
| 오류 진단 | 위 정보 + **실패 로그의 마지막 부분** — rsync/tar 출력이라 개별 파일 경로가 섞일 수 있습니다 |
| 검증 리포트 | 매니페스트의 항목별 크기·파일 수와 검증 통과 여부 |
| **환경 조사 제안** | **설치 목록** — Homebrew formula·cask, 응용 프로그램 이름, App Store 앱, VS Code 확장, 전역 패키지(npm/pipx/cargo), 로그인 항목, 홈 최상위 점 디렉터리 이름 |

환경 조사는 목록을 만든 뒤 화면에 먼저 보여 주고, **「Codex 에게 의견 묻기」를 누를 때만** 전송합니다.
무엇이 나가는지 보내기 전에 그대로 펼쳐 확인할 수 있습니다.

즉 "홈 디렉터리에 무엇이 얼마나 있는가"와 "이 맥에 무엇이 깔려 있는가"는 나갑니다. 그게 곤란한 환경이라면
`codex` 를 설치하지 않거나 PATH 에서 빼면 됩니다 — LLM 기능만 비활성화되고
백업·복원은 그대로 동작합니다.

### 안전장치

- Codex는 **읽기 전용 샌드박스**(`--sandbox read-only`)에서 돕니다. 파일을 직접 건드리지 않습니다.
- 제안은 **사용자가 승인해야** 계획에 반영됩니다. 자연어 명령도 해석 결과를 보여 주고 확인을 받습니다.
- 진단이 낸 셸 명령은 **복사만** 됩니다. 앱이 대신 실행하지 않습니다.
- 세션은 `--ephemeral`로 돌아 홈 디렉터리 목록이 Codex 기록에 남지 않습니다.
- 인증은 전적으로 `codex login`에 맡깁니다. 이 앱은 API 키를 보관하지 않습니다.

## 매니페스트와 검증

백업이 끝나면 `manifest.json`이 남습니다. 하드코딩된 기대치가 아니라
**"백업할 때 실제로 이만큼 있었다"** 를 기록한 것입니다.

```
BackupPilot-20260812-200336/
├── manifest.json     # 항목별 크기·파일 수·소요 시간·성공 여부
├── backup.log
└── data/
    ├── .ssh.tar.gz
    ├── dev.tar.gz
    ├── Documents/
    └── Desktop/
```

복원 후 **복원 결과 검증**을 누르면 이 값과 대조합니다.
파일 수가 98% 이상이면 통과로 봅니다 — 캐시가 다시 생기고 제외 패턴 집계 기준도
완전히 같지는 않아서 100% 일치를 요구하면 매번 실패로 뜹니다.

### ⚠️ 홈 경로가 같아야 합니다

Claude Code의 대화 기록은 `~/.claude/projects/` 아래에 **프로젝트 절대경로를 인코딩한**
디렉터리 이름으로 저장됩니다.

```
/Users/me/dev/myproject  →  ~/.claude/projects/-Users-me-dev-myproject/
```

계정명이 달라지면 파일은 복원돼도 `claude --resume`이 과거 세션을 찾지 못합니다.
앱이 매니페스트의 홈 경로와 현재 홈 경로를 비교해 다르면 경고합니다.

## 구조

```
Sources/BackupPilot/
├── App.swift            @main
├── AppModel.swift       전체 상태. 엔진 두 개의 변경 알림을 되쏨
├── Models.swift         BackupItem / Volume / BackupPlan / Manifest / 용량 예측
├── HomeDirectory.swift  "홈이 어디인가"의 유일한 출처
├── VolumeScanner.swift  볼륨 탐색(statfs로 파일시스템 판별) + 크기 측정
├── SystemInventory.swift 설치 목록 수집 (brew/앱/확장/전역패키지). 없는 도구는 건너뜀
├── PlanBuilder.swift    기본 계획 규칙 + 제외 패턴
├── ProcessRunner.swift  외부 명령 실행 (줄 단위 스트리밍)
├── BackupEngine.swift   rsync / tar 실행, 매니페스트 기록
├── RestoreEngine.swift  아카이브 해제, 권한 복구, 검증
├── CodexClient.swift    codex exec 호출
├── Advisor.swift        프롬프트 + JSON 스키마 + 응답 타입
└── *View.swift          화면
```

### 직접 확인해 보려면

`BACKUPPILOT_HOME`을 지정하면 진짜 홈을 건드리지 않고 앱 전체를 돌려 볼 수 있습니다.
이 상태로 돌면 사이드바에 **"테스트 홈 사용 중"** 이 표시됩니다.

```bash
BACKUPPILOT_HOME=/tmp/fakehome ./build/BackupPilot.app/Contents/MacOS/BackupPilot
```

## 알아 둘 것

- **압축은 gzip 고정.** zstd가 3~4배 빠르지만 시스템 `tar`가 외부 `zstd` 바이너리를 요구합니다.
  Homebrew 설치 전 맨바닥 macOS에서 풀 수 있어야 하므로 이식성을 속도보다 앞에 뒀습니다.
- **복원은 덧씌우기이지 동기화가 아닙니다.** `rsync --delete`를 쓰지 않습니다.
  지금 홈에 있는데 백업에 없는 파일은 그대로 둡니다.
- **복원 시 `._` 파일은 걸러냅니다.** exFAT이 만든 것이지 원본에 있던 파일이 아닙니다.
- **용량 예측은 보수적입니다.** 할당 블록 반올림과 AppleDouble을 모두 계산에 넣습니다.
  실제로는 대개 이보다 덜 씁니다 — 모자란 것보다 남는 쪽이 안전합니다.
